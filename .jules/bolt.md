## 2024-05-24 - NodeList allocation overhead in updateSlidesVisibility
**Learning:** `updateSlidesVisibility` is executed on every slide change. Calling `toArray()` on the result of `querySelectorAll` converts a NodeList into an array via `Array.prototype.slice.call`, which creates a new Array allocation every single time, leading to memory overhead and GC pauses on the hot path (especially since this is done inside a nested loop for every horizontal and vertical slide).
**Action:** NodeList provides a `.length` property and array-like index access `[x]`, which works perfectly with basic `for` loops in older ES5 browsers without needing to be converted to a proper Array. Avoid using `toArray()` on NodeLists unless Array prototype methods like `.map()` or `.forEach()` are absolutely necessary.
