## 2024-06-11 - Optimize DOM Method Access in Traversals
**Learning:** During DOM traversal (e.g. `closestParent`), dynamically resolving `Element.prototype.matches` on every iteration adds measurable overhead in tight loops. However, caching the method at module-level requires care in SSR environments (using `typeof Element !== 'undefined'`) and during actual invocation `parent.nodeType === 1` must be checked, otherwise properties like `parent.matches` throw a `TypeError` when the traversal reaches the root `document` or `DocumentFragment`.
**Action:** When caching DOM object prototypes/methods globally in shared modules, wrap them in existence checks to support SSR/non-browser contexts, and always ensure node traversal loops verify node types before attempting DOM-specific method calls.
