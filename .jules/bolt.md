## 2024-05-18 - Caching DOM Traversal Method Detections
**Learning:** In legacy browsers, checking for properties like `matches`, `matchesSelector`, or `msMatchesSelector` on every loop iteration during DOM traversal introduces unnecessary overhead. However, when caching these methods at the module level (e.g., using `Element.prototype`), we must ensure the code runs safely in non-browser/SSR environments by checking `typeof Element !== 'undefined'`. Additionally, when traversing up the DOM tree, we must verify `nodeType === 1` (Element) before calling the cached method to avoid `TypeError`s on `document` or `DocumentFragment` nodes.
**Action:** When optimizing DOM traversal and caching DOM methods, wrap module-level caching in existence checks for the DOM globals, and ensure node type checks (like `nodeType === 1`) are in place before invoking DOM-specific methods.
