## 2024-05-19 - [Cache DOM methods at module level and check nodeType]
**Learning:** In legacy codebases, DOM fallback methods like `matchesSelector` can be expensive to detect on every iteration within traversal loops like `closestParent`. However, when caching DOM methods at the module level in SSR-compatible code, you must wrap them in an existence check (e.g. `typeof Element !== 'undefined'`) to prevent ReferenceErrors. Additionally, when using these DOM-specific methods during traversal, you must first verify that `nodeType === 1` to avoid TypeErrors when encountering non-element nodes like `document` or `DocumentFragment`.
**Action:** When optimizing DOM traversal, cache method existence checks at the module level with a `typeof Element !== 'undefined'` guard, and verify `nodeType === 1` before invoking DOM methods on traversed nodes.
